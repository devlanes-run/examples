# Forty services and the start gate

Forty copies of one no-dependency Node server, split by `templates` into `api`, `web`, `worker` and `job` services, each with its own tag colour. Every service works for a random 1 to 6 seconds before it is ready, then burns a little CPU now and then, so a start fills the machine-wide start gate (`startup.*` in the user config) and the resource monitor (`M` in the TUI) has something to draw. `devlanes.yaml` is generated by `generate.mjs`.

## Requirements

- devlanes, with `devlanes setup` run once
- Node 24 (the server has no dependencies)

## Run it

```sh
cd showcase-many-services
devlanes start
```

Open https://many-services.localhost. The index page lists all 40 services of lane 0 (one worktree's ports, hostnames and data) with a link to each, its kind, how long it took to get ready, its CPU bursts and CPU time. It asks every service for `/stats` and reloads every 2 seconds, so during a start you see the count of services that answer go up. `index`, `api-01` and `web-01` have hostnames; the other 37 are port-only, and the index links to their `http://127.0.0.1:<port>`.

## During a start

The start gate decides how many services may be starting at the same time, across every lane and project on the machine. A service holds its slot until its ready check passes: `ready.http` on `/healthz` for `api` and `web`, the log line `ready after` (`ready.log`) for `worker` and `job`. The rest wait as `queued`. With the default `startup.mode: adaptive`, the window starts at `startup.max`, which defaults to the number of CPU cores. It halves after 3 seconds above 90% CPU or under memory pressure, and grows by one slot every 2 seconds while system CPU stays below `startup.target_cpu` (75%).

On a 20-core machine, 20 services started and the rest queued. `devlanes status` during the start, a second in:

```text
many-services
  LANE  BRANCH  STATE     SERVICES  CPU  MEM  URL
  0     main    starting  0/40      –    –    https://many-services.localhost

  job-05     queued 4/23   20595  –    –    http://127.0.0.1:20595
  api-06     queued 5/23   20585  –    –    http://127.0.0.1:20585
  web-06     queued 6/23   20605  –    –    http://127.0.0.1:20605
```

`queued 4/23` is the unit's place in the queue and the queue's length. The queue is shared by the whole machine, so it counts other projects' services too (here another project's `api` was at its head). `devlanes status --output json` has the numbers behind it in each queued unit's `reason`: `"in_flight": 20, "window": 20, "hold": "window_full"`.

Each starting service works in 40 ms slices, about 40% of a core, which `status` shows a few seconds later:

```text
  0     main    starting  3/40      692%  475.6 MiB  https://many-services.localhost
  index      starting      20590  39%   21.4 MiB  https://many-services.localhost
  web-01     ready         20600  0.0%  22.3 MiB  https://web-01.many-services.localhost
```

CPU is a share of one core, so a lane can pass 100%, and the lane row adds up its units. Once all 40 are up, the lane uses about 1 core and 880 MiB:

```text
  LANE  BRANCH  STATE    SERVICES  CPU   MEM        URL
  0     main    running  40/40     111%  883.0 MiB  https://many-services.localhost
```

In the TUI, api services are cyan, web green, workers magenta and jobs yellow (`tags` with `color`).

## Try next

- Press `M` in the TUI that `devlanes start` opened. The monitor shows every unit on the machine, grouped by lane, with CPU and memory graphs on top. `/` filters (type `many-services job` and Enter: the title shows `units /many-services job 9 of 110`, since every word has to match). `<-` and `->` move the sort through name, lane, kind, state, cpu, mem, peak and uptime (`cpu ▼` puts the busiest unit first), `i` reverses it, `e` switches to one flat list with a `lane` column, and Esc clears the filter. The box under the table graphs the selected lane, for example `many-services@0 · main · cpu` with `now 65%  avg 357%  min 0%  max 1454%`.
- `devlanes debug top` prints CPU and memory per lane and unit for every lane on the machine:

  ```text
  many-services@0  cpu 160%  mem 860.1 MiB
    UNIT       CPU   MEM
    api-01     4.7%  22.0 MiB
    api-02     0.0%  20.4 MiB
    api-03     4.7%  20.1 MiB
  ```

- `devlanes stop`, then `devlanes start --no-ui --all-at-once`: the gate is skipped for that run and every service starts at once. On the same 20-core Windows machine, with other projects running, the gated start took 10.5 to 12.0 s (6 runs) and `--all-at-once` 6.5 to 7.2 s (3 runs), while the lane's CPU in `status` peaked at 1327% instead of about 750%. The boot here is wall-clock time; a real dev server that compiles competes for the same cores and gains less.
- `devlanes config get startup` prints the gate settings (`null` means the default):

  ```text
  mode: adaptive
  initial: null
  max: null
  target_cpu: 75%
  settle_cpu: 10%
  slot_timeout: 20s
  reserve_memory: null
  ```

  To change them, edit `~/.devlanes/config.yaml` or use `devlanes config set startup.max 8`, `devlanes config set startup.initial 2` (ramp up from 2 slots), `devlanes config set startup.mode fixed`, `devlanes config set startup.target_cpu 50%` or `devlanes config set startup.slot_timeout 10s`, and `devlanes config unset startup.max` to go back. They apply to every project on the machine, so these commands were not run for this README.

- `devlanes logs worker-01 --tail 4` shows the bursts of a worker:

  ```text
  worker-01#57 handled batch 13 in 250 ms
  worker-01#58 handled batch 14 in 172 ms
  ```

- `node generate.mjs 12` rewrites `devlanes.yaml` with 12 services (`devlanes config check` accepts it) and `node generate.mjs` brings back 40. Run `devlanes stop` and `devlanes start` afterwards.
- Start a second lane: `git worktree add ../examples-checkout -b feat/checkout`, then `cd ../examples-checkout/showcase-many-services && devlanes start`. Its index is at https://many-services1.localhost. This step was not run for this README. In the same folder, `devlanes lane new --name many-services-review --start --no-ui` gives lane 1 without a worktree:

  ```text
  created many-services@1 named many-services-review (main) at D:\dev\devlanes\examples
  many-services@1 · main
  ✓ services  40 of 40 ready
    ✓  index      https://many-services1.localhost
    ✓  api-01     https://api-01.many-services1.localhost
  ```

  Both lanes' 80 services go through the same gate, and the index on https://many-services1.localhost says `This is lane 1 of many-services.`

- `devlanes lane clean many-services-review --yes` and `devlanes lane clean 0 --yes` stop both lanes and free their ports.

On Windows, `devlanes stop` reports each service as `exit=-1073741510`, Windows' exit status for a process ended by Ctrl-C.

## Files

- `devlanes.yaml`: the tags, the `node`, `api`, `web`, `worker` and `job` templates and 40 services. Generated; do not edit it by hand.
- `generate.mjs`: writes `devlanes.yaml`; `node generate.mjs [count]`.
- `server.mjs`: the one server. `KIND`, `BOOT_MS`, `BURST_MS` and `BURST_EVERY_MS` set its kind, boot time and CPU bursts; `PAGE=index` makes it the index.
- `devlanes.css`, `logo.svg`: the page look.
